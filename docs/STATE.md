## 9. 2026-09-12 10:45 北京时间(02:45 UTC) — v0.4.0 实盘归因与策略重校

### 9.1 首次 10 小时 dry-run 的真实结果

| 指标 | 数值 |
|---|---|
| 区间 | 2026-09-11 22:41 → 2026-09-12 09:42 北京时间 |
| 交易 | 56 笔全部平仓 |
| 胜率 | 67.9% |
| 结果 | **-97.35 USDT(-9.7% 权益)** |
| 均盈 / 均亏 | +1.81 / -11.40 USDT(盈亏比 0.44) |

### 9.2 三条归因结论(有数据支撑)

1. **盈亏比是唯一死因**: 胜率 68% 被「亏大赚小」完全抵消 ——
   9 笔亏 -8%~-15% 权益, 31 笔只赚 0~2% 权益。
2. **打分能选币、不能择时**: 6496 样本上
   BTPearson(score, 未来 60 分钟收益) = +0.042BT; 分桶平均收益近乎持平。
   因此打分门槛从 12 提到 20, 只做多因子共振。
3. **杠杆×止损距离是真正的风险来源**: 4x × 12% = 单笔 48% 权益敞口。
   现改为 3x + 距离钳制 2%~8%, 单笔最坏风险被压到 0.8%(上限 1.2%)。

### 9.3 新发现的有效因子: 榜单稳定性(stick)

| 类型 | 特征 | 实测样本(北京时间 09:50) |
|---|---|---|
| 持续趋势票 | 平均名次 2~6, 连续在榜 180~240 分钟 | LAB、龙虾、RAYSOL、RIVER |
| 脉冲票 | 上榜首多但每次仅几分钟 | 多数新进榜小币 |

因子由 BT连续在榜时长(45%) + 在榜占比(30%) + 平均名次(25%)BT 合成, 权重 18。
策略侧: BTSTICKYBT +25% 仓位 / BTBURSTBT -30% 仓位 / 低于 0.25 不开仓。

### 9.4 验证方式

* 30 条单元测试(BTbash scripts/dshc-test.shBT)守护两大量纲不变量与稳定性因子语义。
* BTpython3 scripts/dshc_trades.pyBT 做交易归因(盈亏结构/离场原因/方向/信号/标的/时长)。

## 12. 2026-09-12 13:40 北京时间(05:40 UTC) — v0.5.0 止损定稿与限流治理

### 12.1 止损数学: 四条不变量(定稿)

复盘发现两个独立缺陷(都不是「入场」层面的问题):

| 缺陷 | 现象 | 修复 |
|---|---|---|
| 盈利保护基准错误 | 用**当前浮盈**做保护 → 浮盈回撤时止损被**放宽**(3.2% 时距离 0.64%, 10% 时反而 2.0%) | 改用**峰值浮盈**(由 trade.max_rate 反算) |
| 分档上限非单调 | 写成 atr×倍数, ATR 较大时高档上限反而更宽 | 改为**绝对距离表** |

最终距离表(单次收紧, 随峰值浮盈递减):

| 峰值浮盈 | 止损距离 | 阶段 |
|---|---|---|
| < 3.2% | 5.2%(或 2.2×ATR, 钳制 2.5%~8%) | initial |
| > 3.2% | 3.5% | trail+fast1 |
| > 6.0% | 3.0% | +fast2 |
| > 25% | 2.8% | +tight1 |
| > 60% | 2.6% | +tight2 |
| > 120% | 2.5% | +tight3 |

四条不变量写入 stops_core 的 docstring 与单元测试:

- **I1** 距离始终 ∈ [DIST_MIN=2.5%, DIST_MAX=8%]
- **I2** 止损位置(peak/leverage − d)随峰值浮盈**单调不减**
- **I3** 距离随峰值浮盈**单调不增**
- **I4** 权益风险 = d × leverage

测试改为**性质测试**: 12 组(ATR×杠杆) × 40 个峰值点全扫描, 共 28 条测试, 0 违例。

### 12.2 捕获率优化

实测盈利单的价格峰值中位仅 +1~2%, 原设计只吃到约 1/3:

- 分批止盈阈值从 +10%/+30% 改为 **+5%/+12%**(小利润才是常态)

- 唯一的大赢家: VTHO 单笔 **+48.82% 权益**(价格走 +20.8%) —— 证明该策略确实能抓插针行情

### 12.3 限流治理(429 的真实原因)

**现象**: 两个 bot 在 3 分钟内各出现 88 次 429, 造成行情数据缺失、可能漏信号。

**根因**: 看板 /api/pairlist 每分钟返回**全新排序**, 导致 freqtrade 白名单持续抖动;
每换入一个新交易对都要重新拉取 5m+1h 启动历史 K 线, 请求量瞬间放大并突破
币安「每 IP 2400 weight/min」的共享配额(该 IP 上还有其它项目的实例)。

**修复**: 候选池加入**迟滞** ——

- 最短 10 分钟才允许换池(PAIRLIST_MIN_INTERVAL_S=600)
- 变动幅度 < 20% 时沿用旧池(PAIRLIST_MAX_CHURN=0.20)
- 大变动时也**优先保留仍然合格的旧成员**, 新成员补位
- refresh_period 从 60s 提升到 600s

**效果**: 429 从 88 次/3分钟 降到 2 次(仅重启瞬时), 随后 0 次。

### 12.4 资金费机制验证(实测)

68 笔交易中 6 笔有资金费记录, 合计 **+0.2146 USDT**(净收入)。

这是**实测结论**; 只有持有时间拉长到数小时后, 费率才会成为主要成本/收益项。

## 14. 2026-09-12 14:40 北京时间(06:40 UTC) — 实验 E: 费率极值反转做空

### 14.1 设计(先算数据, 再写代码)

**经济逻辑**: 当某合约资金费率处于**其自身历史极值**时, 说明多头拥挤到愿意支付极高成本持仓。
此时做空有两重收益: ① 每期结算**多头付钱给空头**(直接现金流); ② 杠杆多头被迫平仓时的价格回落。

**关键设计决策 —— 用自适应分位而非绝对阈值**:

实测当天全体候选的最大年化费率仅 **5.5%**, 而个别标的的历史极值可达 +200% 以上。
若把门槛写死成「年化 ≥ 100%」, 在费率平淡期将**永不触发**; 在费率普涨期又形同虚设。
因此改用「该币自身历史分位 ≥ P90」, 可自适应任何市场环境。

| 门槛 | 值 |
|---|---|
| 费率分位(自身历史) | ≥ 0.90(样本 ≥ 30 时启用) |
| 绝对回退阈值 | 年化 ≥ 20%(历史样本不足时) |
| 24h 涨幅 | ≥ 25%(已有回补空间) |
| 4h RSI | ≥ 70(超买) |
| 大户持仓多空比 | ≤ 1.35(避免空头自己拥挤) |
| 离场 | 费率跌破入场值的 50% / 分位回落至 0.55 以下 / 最长 36 小时 |
| 风控 | 杠杆 **2x**、风险预算 0.7%、硬上限 1.0%(空头挤压风险更高) |

### 14.2 基础设施修复: 费率历史回填断链

排查时发现一个**断链缺陷**: 早前为省请求删除了逐币 `/fapi/v1/fundingRate` 轮询时,
把**历史回填也一起删掉了** —— 导致 `funding_hist` 每币上限只有 12 条, 分位数根本算不出来。

修复:

- 恢复该任务, 但改为**轮转分批**: 每轮 8 个合约 × 最多 120 条(约 40 天历史), 周期 900s
- 首次遇到某合约时拉长历史, 之后只增量补 12 条
- `funding_hist` 保留期 30 天 → **420 天**(费率极值判断需要长历史)

验证: `funding_hist` 行数 480 → **1301+**, 单币样本 12 → **120**, 候选池已带
`funding_pct_rank` / `funding_p95` / `funding_samples` 字段(实测 7/64 个候选已有足够样本, 随轮转持续增加)。

## 18. 2026-09-13 08:45 北京时间(00:45 UTC) — ⚠️ 重大发现: 此前所有「信号检验」口径错误

### 18.1 事故: 同一条件在不同脚本里结论相反

统一检验时发现: 「15 分钟跌超 5%」在早前的 BTmomentum.pyBT 里是 **+2.379%(胜率 58.2%, n=201)**,

逐行排查后定位根因: 检验脚本里写成

```python
b3 = v[i - 3][1]        # ← 3 个采样点
m15 = (px / b3 - 1) * 100   # ← 变量名叫 m15, 实际是「3 分钟动量」
```

**把 3 分钟动量当成了 15 分钟动量使用。** 由于 BTticker_snapBT 是 1 分钟粒度,
`i-3` 是 3 分钟, 而 15 分钟应为 `i-15`。这解释了样本数 98 vs 610 的全部差异。
